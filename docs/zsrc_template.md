## ⚠️ Scope 告警（2026-10-29 规则页核查后置顶，优先级高于下文一切内容）

对 zcode.z.ai/cn/zsrc/rules 的核查结论：
1. **该 ZSRC 收的是 ZCode 产品**（桌面客户端/CLI/IDE 插件/官方扩展），**未列 GLM 开放平台 API 为独立资产**；
2. **纯"违规文本生成"明确不算漏洞**（原文排除：模型角色变化、错误回答、违规文本、一般性幻觉）；
3. **可收录的 AI 模型类漏洞**：提示词注入/上下文污染导致**未经授权的工具调用、数据访问或外传、代码执行**等实际安全影响；
4. 随机性问题须附测试次数/成功次数/触发条件；未经书面授权不得公开细节。

**对我们的影响与修正后的披露路径**：
- 路线 A（仍有效）：若在**智能体/工具调用场景**下发现越狱 → 工具误调用/数据外传，才构成本 ZSRC 收录范围。这要求把实验升级到 agentic 场景（工作量大，作为后续项目）。
- 路线 B（已核实 2026-10-30 页脚实查）：zhipuai.cn 页脚**无专用安全邮箱**（仅商务 service@zhipuai.cn、电话 400-6883-991），漏洞报告统一导向 ZSRC 入口（/zh/zsrc）；bigmodel.cn 为 JS 渲染页、抓取不到页脚（**需人工浏览器核查**）。结论：线上模型侧发现的实用告知链 = ①service@zhipuai.cn 私密邮件（注明安全事项请转安全团队）②open.bigmodel.cn 工单 ③漏洞盒子资产栏注明 bigmodel.cn。
- 路线 C（默认）：**白盒开源权重分析本就不要求披露**——博客只发方法论与本地实验结论；线上 API 侧若无 agent 级影响，仅做负责任的私密告知（邮件渠道），不做正式漏洞提交。
- 红线不变：任何线上测试低频、手动、自建账号；不发布利用代码。



> 提交渠道：https://zcode.z.ai/cn/zsrc → 漏洞盒子平台（官方唯一确认渠道）
> 纪律：只提交线上 API 侧（黑盒提示词）的发现；白盒权重分析不构成漏洞，写 blog 即可。
> 提交前确认：使用自建账户/自建测试数据；不含 DoS/扫描/批量获取行为（ZSRC 规则页）。

## 提交节奏与礼仪
1. **先白盒后线上**：本地权重实验完成 → 线上 API 验证（少量、低频、自建账号）→ 整理报告 → 提交。
2. **一次一漏洞**：每个提示族单独提交（平台按漏洞计数与评级），不要打包。
3. **响应等待**：平台初审（漏洞盒子）→ Z.ai 安全团队复现 → 定级 → 修复。公开 blog 前确认：已获修复确认或提交后满 30 天（行业惯例的 coordinated disclosure 窗口）。
4. **留痕**：所有往来（提交编号、沟通记录）存 `docs/disclosure_log.md`（提交通知后新建）。
5. **红线自检**：提交内容不含可批量滥用的自动化脚本；不含真实用户数据；测试频率以人工手动为限。
