# 开放权重收紧的风险与对策

> 背景问题：如果厂商不再公开安全相关权重（怕被滥用），这个项目还做不做得下去？

## 一、先把事实说准

**不是"权重不公开了"，而是收紧的具体形态在变。** 观察到的几种做法：

1. **只放 base / 不放 instruct**：安全对齐版本被留下，因为红队与越狱研究直接针对它。
2. **放权重、不放数据**：训练语料、安全 SFT 数据、红队集不公开（这一直是常态，Open-R1 就是为补这个空缺而建）。
3. **延迟发布或分阶段发布**：先 API，后权重；或先小模型后大模型。
4. **许可证限制用途**：禁止用于安全研究/红队/对抗测试（部分社区许可含此类条款）。

但同期仍在持续放出**重量级开放权重**：Qwen2.5/3 系列（Apache-2.0）、Llama-3.1/3.3（社区许可）、Gemma-2/3、**OLMo-2/3（Apache-2.0，连训练数据都开放）**、Mistral、InternLM2.5、MiniCPM 等。所以"完全做不了"不成立。

**关键事实：我们依赖的三个模型都已到手。**
- GLM-4-9B-Chat（MIT）、DeepSeek-R1-Distill-1.5B（MIT）、Qwen2.5-1.5B-Instruct（Apache-2.0）
- MIT/Apache 类许可授予的副本**不可撤回**——即使仓库下架，我们手上的副本仍可合法使用与再分发（保留许可声明）。见 `MODELS.lock.json`。

## 二、为什么这个风险不致命

本项目的方法论是**模型无关**的，不依赖某一家：

- 命题 2（消融/注入验证）、命题 3（Δproj 预测越狱）、位点扫描、跨话题余弦矩阵，都是"任意 decoder-only 模型 + 一次前向读数"就能跑。
- 我们已经拿到 **GLM-4-9B 的完整首轮结果**（基线、层扫描、位点不对称、AUC 阴性）。这部分不因未来发布策略改变而失效。
- 目前最有价值的发现（**注入只在 L15–L23 有效、读出在 L38** 的位点不对称）已经成型，属于机制层结论，复现只需一个开放 9B 级模型。

## 三、三层兜底（按可执行性排序）

### L1 本地归档 + revision 锁定（立刻可做）
- `MODELS.lock.json` 记录 repo、revision（HF commit hash / ModelScope 快照日期）、许可、层数、hidden。
- 至少保留一份本地副本：**建议把 GLM-4-9B-Chat 的 18GB 快照从 GPU 节点拉回一台长期存储**（当前节点失联，若彻底丢失需重新下载，ModelScope 仍在）。
- 复现脚本固定 revision（`snapshot_download(revision=...)`），避免"同名不同权重"。

### L2 备用模型清单（已写入 MODELS.lock.json）
优先选**许可最宽松 + 全开放**的：OLMo-2（Apache-2.0、含数据）> Qwen2.5/3（Apache-2.0）> Llama-3.1（社区许可，但文献基准）> Gemma（条款较严）。

切换成本极低：`_decoder_layers()` 已覆盖 `model.layers / transformer.encoder.layers / transformer.h` 三类命名，换模型只改 `--model`。

### L3 黑盒降级路线（最坏情况）
若某天只剩 API 可用：
- 仍可做**行为层**：5 提示族成功率、成对话题边界精度、过拒率——即我们 baseline_audit 那套，不需要权重。
- 若有 logprob（部分 API 提供），可做 Adaptive Attacks 式的 logprob 随机搜索，与我们"响应首 token"判据同源。
- 白盒部分（方向提取/投影）写成"开放权重不可得时的限制"，反而是有信息量的诚实声明。

## 四、把风险变成内容（提议）

在 blog/论文加一节 **"开放权重是安全研究的基础设施"**：

1. 给出可用性矩阵：模型 × 是否开放权重 × 是否开放安全数据 × 许可是否允许安全研究。
2. 说明我们的框架对"半开放"生态的适配：base-only 模型也能提取方向（本项目的 R1-Distill 零拒绝对照正是这种情形的样本）。
3. 明确伦理边界：只做开源权重白盒分析；线上 API 发现先披露（见 `docs/zsrc_template.md`）。

这一节会同时满足三件事：解释我们为什么选这些模型、回应"厂商收紧"的现实、以及给社区一个可复用的清单。审稿人与厂商安全团队都会认这个。

## 五、结论

实验不用改方向，但要加两条工程纪律：**锁定 revision + 本地留存副本**。科学结论层面，我们已经掌握了所需模型的副本与首轮结果；生态层面，把"可获得性"做成一张表，比视而不见更专业。
