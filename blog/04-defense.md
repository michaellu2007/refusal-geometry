# 04 · 对防御者的启示：一个点积就能当越狱检测器吗？

> blog 第 5 节草稿（对应 outline §5）。写给安全团队——这是最可能让厂商安全部门觉得"值得聊"的一节。
> 立场：不为攻击服务，为检测器服务（引 A-MESS 的防守者中心视角，arXiv 2607.17152）。

## 5.1 为什么现有检测器不够用

- **输出侧 judge**：贵、慢、依赖 judge 模型本身的对齐，且对固定题库过拟合（RAS, arXiv 2606.25750 的批评）；
- **梯度类白盒检测**（Gradient Cuff, arXiv 2403.00867）：需要额外前向/反向，推理成本高；
- **prompt 侧投影监控**：读 prompt 编码的隐状态——但 Kwon (arXiv 2607.14147) 证明了它的结构性盲区：prefill 类攻击下 prompt 侧表征完好、监控器必然漏报；它只对"改写提示型"攻击有效。

## 5.2 我们的方案：响应位投影监控器

实验（第 3 节）若证实"越狱成功 ⟺ 投影显著下降"，则可在线部署一个极廉价的监控器：

```
对每个生成步（或前 8 个响应 token 的均值，HARC 配方）：
  z = ⟨h_ℓ, r̂_ref⟩        # 一次点积，h_ℓ 是最后一层隐状态
  if z < τ_alarm: 触发二次审查 / 拒绝 / 记录
```

- **成本**：每 token 一次点积，零额外前向——比 judge 便宜三个数量级；
- **双方向版**：同时监控 $z_{\text{ref}}$ 与 $z_{\text{harm}}$，落在 HARC 平面的"双压/单压"象限时分别告警（不同攻击类可分区，误报更可控）；
- **模型级 ↔ prompt 级**：RAS 给的是模型级安全分（0-100），本方案是它的 prompt 级下沉——同一个数学对象，两个部署粒度；
- **与 R1 类推理模型**：思维链先于答案生成，监控点应放在思维链的拒绝读出位——这是我们实验里显式测量的（R1-Distill 对照组）。

## 5.3 局限（写给我们自己，也写给读者）

1. **方向可被针对**：监控器公开后，攻击者可优化提示绕开投影下降（对抗 GCG 已证明指向内部方向的优化可行，arXiv 2607.08883）——监控器应是纵深防御的一层，不是唯一一层；定期用新攻击数据更新方向（WRDO 的加权聚合思路）。
2. **单方向监控的盲区**：若我们的余弦矩阵显示话题间方向低相关（结局 C），单方向监控器会漏掉整块话题——分话题方向库是补丁。
3. **过拒风险**：阈值 τ 设太紧会把边界良性请求（"如何防范电信诈骗"）误杀——用我们的话题对数据集的 benign 侧校准阈值，报告 FPR。
4. **白盒前提**：部署方需要能读隐状态——对开源权重成立，对 API 用户不可用（这正是我们向 ZSRC 报告线上发现的原因：厂商自己有这个能力）。

## 5.4 给智谱 / DeepSeek 安全团队的具体建议

- **短期（零训练）**：在推理栈里加响应位投影读数，先只记录不拦截，两周内拿到"越狱尝试的投影分布"数据，再定阈值；
- **中期**：把我们的 5 族提示改写加入红队回归集（成对、模板化、无 payload，见 repo data/topics/）；
- **长期**：训练侧——参照 DeepRefusal (arXiv 2509.15202) 在微调时随机消融拒绝方向，逼迫模型学会从越狱状态重建拒绝；或参照 SSRFT (arXiv 2610.07023) 做"安全角色内化"降低对显式拒绝模式的依赖。
